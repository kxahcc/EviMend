# 评测口径与接受规则

状态：研究评测设计，新增实验尚未启动。最后维护：2026-10-26。

## 评测回答什么

研究需要同时回答：修复是否满足独立判据，机制是否改变了实际调查和修改，以及同预算下收益是否抵得过额外成本。软件自检、机制消费、样本修复与总体方法优势分别提供证据。

## 指标及分母

| 指标 | 定义与条件 |
|---|---|
| 可运行覆盖 | 所有预选任务中完成原故障复现并有正常行为判据的比例，列出排除原因 |
| 修复通过率 | 冻结任务中最终候选通过独立故障、正常/边界及回归检查的比例 |
| 安全修复 | 已知 PoC、独立变体及功能检查分别报告；阻断单一输入不直接当完整修复 |
| 定位准确性 | 只有可靠独立真值时计算；无真值时报告定位输出和证据，不冒充准确率 |
| 候选与修订 | 候选数、失败类别、重新调查次数及最终状态，保留有效任务中的失败 |
| Pass@k | 预先明确独立尝试定义、采样过程和分母；同一任务连续修订不是独立样本 |
| 成本与时延 | 输入缓存命中、未命中、输出 Token；实际模型费用估算；执行与总墙钟时间 |
| 上游衔接 | 同时报发现后条件修复率及最初任务分母下的全流程完成率 |

原运行与独立评测使用的源码、输入和判据均需固定。未执行、证据不足或执行失败不能补为 pass。任务谱系与日志表示变形分开计数，不用相关变体扩充独立样本分母。

## 比较与消融

固定基础模型、模式、工具权限、知识、允许输入和总预算。基础系统应有正常读取、编辑和验证能力，不能通过剥夺常用工具制造增强收益。

优先比较基础 Agent、普通历史/摘要方式、最接近的公开方法，以及移除关键选择/反证/诊断修订机制的单因素组。是否纳入某项消融取决于它确实参与实际决策。记录新增成功、退化案例、调用和执行成本，不把已实现但未消费的功能写成实测增益。

上游发现交接可比较报告与 PoC、完整历史、结构化证据等输入方式；每组使用同一组已确认缺陷，避免把发现质量差异算成修复策略收益。

## 独立验证与数据隔离

开发样本用于调试和机制选择，正式样本在策略确定后评测。优先按项目或缺陷谱系隔离，记录公开修复历史可能带来的污染，不向求解上下文提供参考补丁或隐藏检查。

Agent 自建测试可以帮助搜索，但最终判据来自项目测试、规范、独立实现或独立审查。给定 PoC 与额外变体分开；语义正确性必须包含原有正常功能。变体预期应独立确定，不能只由同一个求解 Agent 自证。

技术中断与真实业务失败分开记录。排除规则在比较前确定，同等作用于各组；不在看到方法优劣后选择性移除。全部实际开销仍用于运行预算和研究成本解释。

## 费用与实验授权

本次仓库迁移不启动新付费实验。新研究的模型、模式、任务范围、单次限制、批次金额和保留额尚待确定，旧 Key 和旧清单不自动授予新的消费额度。

单任务预算与批次上限分别约束。费用按当次固定提供方价格、已保存 usage 和确认的缓存拆分计算；未命中输入、命中输入和输出分别列示。推理 Token 若为输出子集，不重复相加。真实账单与估算注明区别。

未知发送或缺失 usage 不补零，也不自动重发。历史已获授权的请求预留只适用于原名单和原预算；新研究运行需要独立约定。清理、归档和重命名不能抹掉实际费用或给恢复任务增加预算。

## 验证接受条件

analysis 只能产出分析/候选；synthetic 只证明软件流程。source_execution 必须执行实际原版和候选的相关源码，披露抽取、转译、mock、输入及覆盖；application 需要完整工程与相应运行环境的执行事实。

原版应在指定条件下复现目标故障，候选须通过同一故障输入、正常/边界行为及回归。只读日志、文本模式检查或用另一份算法代替源码不能作为候选执行。通过判据只说明其覆盖范围，不等于普遍正确性证明。

## 当前离线聚合的口径

metrics.py 的既有 offline_synthetic 清单只处理对应历史 schema 和停止记录，保留旧 session/report/completion 配对与未知字段。它不能通过重命名直接计算新的真实项目修复率；真实评测必须接纳执行协议、独立判据与实际原件。

后续正式结果至少包含：任务及版本清单、共同配置、独立检查、候选 diff、失败与修订、缓存/费用/耗时、机制实际消费和重跑命令。证据范围见[模块契约](../design-contracts.md)，推进阶段见[研究计划](../project-work-plan.md)。
