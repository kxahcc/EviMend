# 评测口径与比较规则

状态：当前内部评测规格，离线聚合可自检，应用评测未执行。最后维护：2026-10-05。
职责：唯一维护指标、对照、统计与评测接受条件。阶段与试点数量见 [实施计划](../project-work-plan.md)，运行结果见 [STATUS](../STATUS.md)。正式口径仍须核对组委会最终规则。

## 指标及分母

| 指标 | 定义与边界 |
|---|---|
| 根因 Hit@1/Hit@3 | 编辑前冻结原源码上的有序根因位置，与独立核验标签比较；初始与最终定位分开，未输出算未命中 |
| 行级标签覆盖 | 报告有可信标签的数量和全部任务数量；无标签不伪装为定位错误或成功，补丁落点不自动等于根因 |
| 应用修复成功率 | 原始版本在目标协议下能触发故障，补丁版本通过预定的构建、目标回放及必要检查；分母是冻结的全部评测任务 |
| 功能正确性 | 独立行为依据与正常/边界测试支持预期结果；仅不崩溃或通过模型自建测试不足以确认，未确认项单列 |
| 回归引入率 | 在原本能通过的行为上出现新失败；须披露基线行为覆盖与分母，不把它混同于方法间成功损害 |
| 首次候选通过率 | 首个完整 diff 在任何专属检查前登记，通过所有必要验证才算成功；局部失败、无补丁、生成失败均留在总任务分母 |
| 资源消耗 | 全部模型调用的实际 Token、费用，工具/模型调用数、修复轮数和关键路径深度；包含失败、探针、重试及回退 |
| 定位耗时 | 任务开始到首次有效根因输出，含相关预处理；未输出/超时的数量与已耗时单列 |
| 修复耗时 | 任务开始到接受或终止，含构建/排队/回放/回归；报告全任务均值、P50/P95、超时率，成功子集单独标注 |

输入/环境接纳规则在比较前冻结。接纳后失败、阻塞、空结果都保留，不能根据某方法的结果事后改变分母。未运行、阻塞或证据不足都不计 pass；机器状态枚举以 [模块规格](../design-contracts.md) 为准。

费用缺失为 null。Token 保存输入、输出和供应商提供的缓存/推理字段，避免重复计数。用实际模型标识、源码/补丁/配置/协议哈希和唯一运行标识绑定成绩；缓存复用必须版本一致。

## 对照与消融

| 组 | 配置 | 用途 |
|---|---|---|
| B0 | 强模型、日志/源码、完整基础工具和反馈修复循环 | 有竞争力的基础闭环 |
| B1 | B0 加结构化诊断交接 | 检验成熟诊断组织的收益 |
| P | B1 加约束追踪和诊断探针选择 | 检验拟议增量机制 |

同模型、同输入、同工具权限、同总预算、同最终验收协议。普通构建/测试反馈在所有组都存在；P 的诊断、检查和回退没有免费预算。P 的义务绑定/约束追踪与决策相关检查选择分别可关闭，消融配置在执行前登记。

真实应用评测规划在用户本机进行。各组共用同一受管 SDK/设备或模拟器配置，应用作业串行；逐次记录工具链版本、设备身份与状态、环境重置、源码/协议哈希及资源限制。设备断连、环境漂移和本机资源中断按 blocked/inconclusive 披露，不当作某个方法的功能失败；冻结后的任务仍保留在总清单，不能按组别选择性删除。基础模型拟由本机 Agent 调用云端 API；所有组必须固定同一实际提供方/模型标识、请求参数和计费边界。

参考论文自行适配不等于复现原方法。论文扩展须补合理的近邻比较，不能只胜过人为削弱的基础提示。具体模型、预算和软件版本尚未冻结，待资源与开发数据支持后确定。

B0 是必须超过的强基线，不只接收简陋提示：它可以自主读写代码、运行同等检查、利用失败反馈继续修复，并使用同一 SDK 的上下文管理。框架版本、默认工具、子代理开关、通用压缩能力和计费方式保持一致。拟议上下文选择消融只改变预登记的发送视图组织方法，总限额和基础能力一致。HarmonyOS 工具和独立业务验收在各组共享；产品适配的价值与决策机制的收益分开报告。

先实现并核验 B0 的工具和循环可用性，再筛选增强，不能用未调通的基线作比较对象。提示与配置只在开发数据上调整，确认集前冻结。直接路径/查证路径的选择只使用求解时可见信息，不事后按成绩路由；简单/歧义等分层标准也须预先定义，不能把基线失败直接当作困难标签。

| 设计假设 | 要记录的过程证据 | 对应最终指标 | 不能据此单独宣称有效 |
|---|---|---|---|
| 来源追踪改善定位 | 原源码上的初始根因排序、相关值的来源引用 | Hit@1/3、首次候选通过率 | 引用完整或栈映射正确 |
| 行为义务减少错误修复 | 义务来源、候选关联、独立验收发现的行为违例 | 功能正确性、回归引入率、应用修复成功率 | 模型自评已满足义务 |
| 选择性检查减少试错 | 追加检查的原因、实际结果、前后修法和成本 | 首次通过率、总 Token、调用数与修复耗时 | 做了更多检查或改变了动作 |
| 反例关联减少空转 | 候选及反例版本、后续修改、重复稳定失败 | 修复成功率、轮数与总成本 | 对话中出现反思段落 |

## 排除“只是更长提示或更多资源”的解释

主比较保留 B0/B1/P；机制确认再加入以下对照，具体运行数量随预算冻结，不立即启动实验：

- B1 加同样的规则文本，但不维护义务与候选/反例关联：区分知识提示与跨步骤机制。
- P 的两个开关组成消融组合，使用相同底座、知识、工具和上限，判断各模块及组合的增量。
- 固定追加一次可执行检查的策略：与按决策需要触发检查比较；实际成本照实统计，没使用的预算不强行花完。
- 若引入独立 mini-swe-agent 适配作为外部工程参照，单列软件版本和适配差异，不冒充同底座消融或官方复现成绩。

对简单直接修复、根因歧义、行为保持和能力缺失分别报告结果。真实缺陷组用于主成绩；去行号/日志噪声等变换只作为明确标记的鲁棒性分析。开发案例用于调参，确认案例按应用谱系隔离。

机制观测包括：真实反例违反业务义务的次数；检查有结论/无结论、导致选择变化的次数；每次任务完整模型/设备开销；由于错误义务或过早停止造成的损害。"改变了动作"不等于"帮助了修复"，仍需关联成对最终结果。没有检查的任务不纳入探针有效率分母，并报告覆盖数。

有限条件另记录输入来源、操作绑定、采样范围/一致性、平台适用性和计算状态。数学谓词 satisfied/violated 不能单独计作真实诊断探针有结论；未实际触达、采样不一致或平台前提未知须单列。源码 literal、静态推断和 synthetic 计算不进入真实运行/应用成功分母；采值、解析、观察副本构建及失败恢复的实际成本也计入共享预算。这些是拟议统计口径，具体记录须随采值接口实现后接入，不把已有合成测试轨迹当成效果数据。

## 上下文、经验与 Skill 的拟议比较

主比较保留 B0/B1/P；工作上下文、经验适用性和 Skill 演进作为可关闭的增量，先分别筛选，不预设全部组合最优。机制契约见模块规格第 3.1 节，实际实现与验证见 STATUS。离线清单 1 保持原比较门，2 仅新增显式 working_context_enabled 因素；3 在同一比较结构中固定共用知识，支持普通经验检索运行。清单 4 已显式接入三态 applicability_enabled，仍共用同一完整知识、工具定义和预算。Skill/学习因素尚未接入，不能擅自改变知识配置或放宽原检查来比较它们。

### 新机制的比较身份与成本归属

完整学习入口后续须冻结 ResearchProfile 和 KnowledgeSnapshot，登记每个比较允许变化的因素；现有工作上下文及三态开关分别由 context_profile/applicability_profile 冻结；下面是接入契约，不是当前 CLI 已支持的选项。配置、内容和实际发送行为须相互核验，仅加一个组名不能建立可比性。

| 因素 | 拟议值和允许差别 | 仍须一致 |
|---|---|---|
| working_context | 关闭 / 义务引用闭包组织；仅改变当前已登记内容的选择与组织 | 同知识池、startup、工具能力、通用压缩策略、总请求/Token/时间预算；选择与完整 wire 成本计入 |
| experience_access | 关闭 / 普通检索 / 前提审查交接；普通检索与审查共享投影和查询限额 | 同经验快照、完整前提/过程/验证范围及可见输入；不删除对照前提或 unknown 条目 |
| skill_snapshot | 人工种子静态 / 开发演进后冻结；内容差别明确属于学习产物 | 同允许学习材料、独立验证协议、学习权限与模型；演进代价保留，不能称这两组知识完全相同 |
| learning_mode | 冻结 / 规则允许的先测后更新；分别统计 | 同初始快照、任务顺序、反馈权限与谱系；在线序列不混入冻结主成绩 |

每次运行保存 selector/retriever 的算法与参数身份、可读内容快照、Skill 文件清单、允许材料范围和学习策略摘要。普通检索与前提审查的查询必须使用同样的当时输入；标签相似度不作为主机语义确认。若要比较检索算法，另登记该差别，不能混入适用性收益。库后续发布不改变已启动运行的身份。

工作上下文的完整审计 packet、求解投影、组织/最终发送和原材料分别核验并记录 UTF-8/原字节量；它们不代替提供方 Token 或完整消息/工具/schema 成本，也不进入修复率。format 2 报告 materialized_bytes 为逻辑引用量，unique_referenced_material_bytes 为按摘要去重的引用量；run_material_observation 为整个 run 的累计 namespace 观察，在多个计划重复展示，不能求和为逐调用成本。材料去重只属工程能力；相关反例引用数量或投影字节减少本身不算修复收益。模型真实使用之后，才按共同预算比较必要义务/反例保留、判断变化、错误尝试及最终效果。

容量压力测试可以声明独立测试时间预算，但须与默认预算失败分开记录，不更改产品默认或正式比较限额。真实实验前须用代表工程核验端到端文件读取/检查耗时，增强本身的全树核验开销计入共同截止时间；容量通过不代表效率门通过。

新增调用用途在调用账本接入前显式迁移：适用性审查、经验提炼和 Skill 修订先登记调用次数，受共同截止时间、已知 Token 停止规则及请求输出上限约束；实际 usage 在响应后登记，当前已知 Token 规则不构成实际总 Token 硬限额。若提案来自已记账 solver，引用该调用且只计一次；独立调用、检索/选择耗时、验证、失败与退回都保留。未知成本保持 unknown，不能补零。开发学习和部署求解分别给出实际成本，再给完整总量；若给摊销值，说明分摊任务数与方法，不能把学习免费化。

| 对照 | 共享内容与允许差别 | 要排除的解释 |
|---|---|---|
| 同知识静态 Skill | 同底座、工具和程序性知识，提供冻结的相同规则文本 | 收益仅来自领域提示 |
| 普通经验检索 | 同一库、条目前提/验证范围、检索预算及可见输入；按普通相关性检索，由模型自行判断 | 收益仅来自获得相似案例 |
| 关闭工作上下文选择 | 保留知识与经验，使用同等通用压缩、回读和预算 | 收益仅来自摘要或上下文限额差别 |
| 关闭经验适用性判别 | 同一库和完整条目，不执行专门的适用/矛盾/未知交接 | 专门判别并未优于模型自行阅读 |
| 冻结 Skill 与开发演进 Skill | 同学习数据范围、模型和业务验收；全部修订/验证成本保留 | 晋升只是反复拟合已见任务 |

关闭研究模块不删除通用 Agent 的读码、反思和验证能力，不隐藏对照可读的经验前提。全部模型用途、检索/排序、查证、失败与回退计入共享预算；未使用的额度不强迫花完。有开发信号后再确认上下文选择与经验适用性判别的交互，不立即展开全部昂贵组合。真实效果仍按根因、修复、功能、回归、首次通过和总成本判断。

过程分析另记录适用性交接及其依据、关键义务/反例在发送视图中的保留、重复错误和未知前提误用。负迁移须用同知识对照的成对新增成功/损害判定；“经验被引用”或“动作改变”不算收益。相似异常却因业务义务或平台语义不同而需要不同修法，是预登记的边界分析；构造反例不代替独立真实缺陷主结果。错误义务、错误经验、无结论检查和过度限制造成的损害全部披露。

## 学习数据与评测隔离

学习材料指经验提炼和 Skill 修订允许使用的数据，不涉及模型参数训练。开发、候选验证和最终确认按应用/模板谱系隔离；条目记录来源及验证范围。确认前冻结经验库、Skills 和配置，隐藏标签/参考补丁/隐藏测试内容不进入求解或经验。同任务多轮、重复日志和近重复源码不增加独立样本；候选选择不能反复使用确认结果。

主成绩使用冻结快照。持续学习若单独评估，先用当前快照求解并计分，再用该任务允许的可见反馈更新；所有方法共享初始库、任务顺序和反馈权限，未来任务不可提前检索。重复运行不会自动获得前次答案，序列任务按谱系统计，顺序实验不冒充新增独立案例。竞赛是否允许跨任务更新须核对正式规则，当前不自动启用。

生成、检索、候选验证和回退的失败成本均保留；学习阶段与部署阶段分别报告，并给总成本。SkillValidationPolicy 须先固定独立开发验证谱系、适用边界反例、旧/新同协议比较、功能/回归、质量允许损失、成本上限、未知处理及候选停止规则。具体数量、容差和阈值依据开发条件预先确定，当前待定；冻结后的实际执行配置只保存这些决定及摘要，不另维护一套门槛。缺协议、缺独立覆盖、结果/成本未知或门槛未定时只能 pending；合成状态转换不取得真实 eligible/晋升资格。有限验证只支持登记范围内的收益，不保证逐例不劣或普遍泛化。

## 验证接受条件

基准原故障复现、候选构建通过、目标动作实际执行、业务结果和预定回归通过、版本链一致，缺一不能宣称按协议修复成功。复跑次数在正式运行协议确定时冻结，当前没有实测校准过的稳定性阈值。

构造测试中的“错误表达式必须存在”不属于修复验收。模型专属探针帮助诊断，不替代独立共同验收。参考补丁、构造答案及隐藏测试留在 evaluator；分析人员已读标签的对话不作为盲测求解上下文。

## 贡献归因及扩展条件

令 n01 为基线失败而 P 成功的独立案例数，n10 为基线成功而 P 失败的数量，N 为完整成对案例数：净提升为 (n01 - n10) / N。同时报告新增成功、损害和总开销，不能只列被挽回的案例。

重复运行先按案例聚合；相关应用按模板谱系分组，不能把重复日志、近重复源码或随机种子当独立样本。区间估计和具体统计检验按最终数据结构预先确定，小样本工程筛选不承担显著性证明。

开发筛选须看到可追溯的机制作用，且收益与新增失败/成本可以解释，才值得扩大确认。没有信号时做由具体失败支持的有限调整，随后选择更稳的配置。确认集运行前锁定主要指标、质量允许损失、停止规则和多重比较处理；这些数值目前待定，不沿用旧规划中的任意百分比。

跟踪诊断支持/矛盾/未知、探针有效率、检查开销及反例影响；引用合法不等于诊断正确。真正执行回退且只使用剩余预算，不能用另一条满预算运行补填成功。

## 最终汇总最少包含

配置与版本、任务总数和标签覆盖、初始/最终 Hit@1/3、应用修复成功、功能正确/未知、回归与首次通过、新增成功/损害、总 Token/费用、调用数、耗时分位数及阻塞/超时数。每个数字可追溯到逐例实际记录，不填写模拟预算或其他论文成绩。

## 当前离线聚合的口径

`metrics.py` 只接纳 `offline_synthetic` 清单和已停止的运行：无知识 session 10/report 7/completion 4 记录实际主机来源和工作上下文发送计划；明确主机批准知识时使用 11/8/5，保存批准配置、原件、查询及实际动作回执；显式三态启停策略使用 12/9/6，另核实际发送输入、冻结上下文、逐前提判断及其动作关联。旧 8/5/2 与 9/6/3 按原契约只读回建。禁止新旧 schema 交叉配对、自动升级或倒填旧来源。它提供软件结果的可核验汇总，不计算竞赛成绩。真实指标仍依赖上述共同应用协议、独立标签和运行记录；没有这些依据，application_metrics 全部为 null，逐行 accepted=false、application_verification=not_run。

输入清单明确列出任务、策略组、repeat 和每个 run，而不是扫描目录挑选结果。所有任务 × 所有组 × 所有 repeat 必须恰有一个格子，run ID 唯一，任务/工作目录不能重叠，重复任务身份、案例键或相同日志字节拒绝。work_path=null 是明确未运行；指定目录不存在或停止后没有报告是 missing，两者均保留在总运行分母。损坏或身份不符的现有证据会拒绝整批汇总，不能跳过后得到更好的数字。任务数量、运行数量和声明的谱系数量分别列出，不把 repeat 或同谱系任务称为独立样本。

每个任务绑定 task.json 原字节、源码/日志、检查协议与主机条件输入摘要。task schema 2 还核对原案例选择对象及其哈希；task schema 1 的案例/谱系/变体仅为清单声明。两者都不证明应用接纳或谱系独立性。各组必须共享模型、工具定义、检索限制、能力、通用压缩和总预算。评测清单 schema 1 只允许登记的 PolicyFeatures 不同，工作上下文保持关闭；清单 schema 2 另显式登记 working_context_enabled 因素，共享其 packet/view 字节限制和近期组数，context profile 只对此 enabled 归一化，其他差别仍拒绝。schema 3 继承 2 并明确共享批准知识的 snapshot/scope、retriever、index_sha256 和全部知识原件清单，只有 task/run 批准按任务绑定，不新增学习因素。schema 4 继续共用 3 的全部配置，variants 另显式登记 applicability_enabled，启停组都使用 session 12、相同工具定义和原总预算；3 保持普通经验代，不能取得 solver-inputs 或三态产物。1/2 不接纳知识运行或知识产物。两类任务 schema 与评测清单 schema 分开核验。聚合核对保存的 session 与清单，重新计算提示、初始任务上下文和工具定义；知识查询从原件重算完整指导，并关联实际 solver/动作/回执，孤立记录不计实际使用。清单内容哈希标识规范化后的全部配置。session 9/10/11/12 的执行来源按保存结构及自洽摘要核验，不要求等于聚合当日 Git/源码/安装环境；旧 session 8 没有的 Git、依赖锁及 SDK 执行版本仍是 not_recorded/null。

已捕获来源的 compatibility_sha256 必须相同，覆盖受限执行源码清单、项目/锁/资源配置原字节及实际 Python/distribution 元数据；其字段归属 [模块规格第 1.2.2 节](../design-contracts.md)。Git 是初始观察，不属于兼容摘要，Git-only 差异单独保留，不视为运行源码相同或不同的唯一依据。存在已知源码、锁或实际环境漂移时拒绝整批比较。新来源和旧/缺失混合时分别报告 captured_records、关联运行、captured_runs、unknown_runs 和 unknown_run_ids；终态缺报告但保存了 session 9/10/11/12 时先核验该来源，11/12 还核验知识与所有查询原件，12 另审读实际输入及三态原件，缺账本不能豁免损坏原件，结果和费用继续未知。不把未发布 session 的本地知识配置升级为主机批准。只有旧来源时保持原 schema 1 汇总结构与完整摘要，确保旧证据包可原样核验。

来源覆盖只表示保存了相应事实，不产生运行成功或完整可复现资格。安装版本是 distribution 元数据，不是第三方二进制校验；主机源码清单只保存路径、大小和哈希，不自动保全未提交 diff 或安装环境。正式比较前仍须固定并保全可重建的主机代码/环境材料，绑定实际 HarmonyOS 工具链、完整运行工程、设备和共同协议，并在观察成绩前冻结任务清单；当前离线来源记录不能代替这些条件。

新清单另外保留工作上下文选择与实际发送核验事实；逐行保存初始/最新/候选关联定位、按 ordinal 排序的全部候选与检查、首次和最新候选、摘要来源及模型/工具成本。synthetic_latest_pass 的分子仅为最终 offline_checked 且最新合成检查 pass 的运行；synthetic_first_candidate_pass 仅看首个已登记候选的合成检查，不能挑历史中最好的一次。两项分母均是该组完整运行数，无候选或未知不计 pass。这些局部文本检查的通过率不能解释为功能正确率或应用首次通过率。

已核验行的全部调用用途与 Token 计入，包含摘要、失败和结果未知调用。缺报告不能当作零成本；缺 usage 或未完成调用使总 Token 为 null，同时保留已知下界、未知行数和已登记调用数。若有缺报告行，总调用数也为 null，分用途数额标明是否完整。实际费用和定位/修复耗时没有来源时保持 null。

成对表以 task/repeat 对齐每两个组，先按 task 列出次数，再给出运行格子的汇总。只有两个结果都确定为合成 pass/fail 才计 eligible：pass 规则同最终通过；fail 须最新检查明确失败且没有未完成模型/工具/检查或模型/上下文错误。其余为 unknown_pairs，不能当作基线失败并记收益。synthetic_gain_count/loss_count 只描述合成运行的改变，不是上述应用 n01/n10，也不提供独立样本统计、显著性或应用净提升。

聚合采用停止标记、原路径链接/硬链校验、源树前后字节及文件身份检查和不可变只读 SQLite；拒绝未合并 WAL/journal，不 checkpoint、不新建账本、不加载答案脚本或执行检查。源码 JSON 作为原始字节保存，不强制转换成主机记录格式。报告写到新的受管工作目录，拒绝覆盖或与输入重叠；命令及格式见 [原型说明](../../src/dfx_agent/README.md)。它提供停止输入的核验快照，不提供对任意外部并发写入者的文件锁。W10 私有导出镜像同一完整矩阵与原始证据，从包内重聚合全文一致，缺失项和未知费用不改变；来源与回读约束见 [模块规格](../design-contracts.md#134-停止记录的本机私有证据导出)。应用评测仍须 W08 的运行条件及独立验收。
