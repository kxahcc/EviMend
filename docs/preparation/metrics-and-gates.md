# 指标、对照与阶段判据

> 数据到位后的实施顺序与小规模诊断计划见 [完整项目工作计划](../project-work-plan.md)。下文 G0/G1 的 3/24 案例门槛属于数据未知时的历史规划；当前以完整计划的 M0–M4 验收和实际可用样本为准。指标定义及统计注意事项继续使用。

以下均为内部建议，未替代组委会最终规则。所有数值门槛是拟采用的决策标准，不是已实现结果，也不是论文录用标准。

## 指标定义

| 指标 | 内部定义与注意事项 |
|---|---|
| 定位 Hit@1 / Hit@3 | 在任何修复编辑前冻结有序位置列表，以原始源码坐标与根因标签比较；未输出算失败 |
| 行级定位 | 仅对有可信根因行标注的子集计算；区分命中任一根因与全部根因覆盖 |
| 补丁行重叠 | 没有根因标注时，只能标作代理指标；开发者改动行不等于所有真实根因 |
| 独立测试通过率 | 固定总案例中，最终提交补丁通过 evaluator 目标测试和回归测试的比例；不是语义正确率 |
| 正确修复率 | 以独立行为依据/补充测试/人工审查确认；未审查或有争议记 unknown 并报告数量 |
| 首次候选通过率 | 首个完整候选在任何候选专属检查前登记，通过全部必要验证才算首次成功；局部检查失败不能抹去首次尝试；失败生成、无补丁均留在总分母 |
| 净收益 | 成对比较中新增加的成功数减去从成功变失败的数量，再除以总案例数 |
| 回归引入率 | 在确认原有行为通过的基线上，修复后出现新失败的案例比例；和方法间净收益的“损害数”不同 |
| 端到端耗时 | 包含读取、索引、诊断、探针、修复、验证与回退；提供均值、P50、P95、超时率 |
| 总成本 | 所有模型调用 Token 和费用，包括失败调用、诊断、选择器与回退；工具计算单独记录 |
| Agent 链路 | 分别给出模型调用数、工具调用数和关键路径深度；不提前认定官方只取其中某个值 |

空结果、超时、无补丁、构建失败和环境异常都保留。正式比较对预先排除的环境不可运行案例披露原因及数量；运行后出现的异常按冻结规则处理，不按方法结果选择分母。

费用缺失记 null，不记 0。Token 同时记录输入、输出和可得的缓存/推理字段，避免重复相加；费用依据供应商实际 usage/账单，不从消息长度猜测。历史版本不同、模型别名变化和限流都需要留痕。

每次运行记录独立标识、源码版本、模型实际标识、配置哈希、补丁哈希和测试版本，区分模型缓存与评测结果缓存。不同候选补丁必须获得对应的实际评测，不能因复用运行标识而读取旧结果。工程接入细节见 [实验计划](pilot-plan.md)。

## 量化新增收益与新增损害

令 n01 为基线失败而 P 成功的数量，n10 为基线成功而 P 失败的数量，N 为完整成对案例数。

    净提升（百分点）= 100 × (n01 - n10) / N
    新增成功率 = n01 / N
    新增损害率 = n10 / N

例如净增加 2 个成功案例在 24 例上等于 8.33 个百分点，这只是算术示例，不能写成本项目结果。报告 n01 和 n10 可以防止“救回几个难例”掩盖破坏原成功案例的情况。

同案例多次运行先按案例聚合，不能把三次重复当作三个独立缺陷。建议案例级成对 bootstrap，项目级聚类做敏感性分析；单次二元结果可使用成对二项/McNemar 方法。种子固定不代表不同 Agent 分支拥有相同随机过程。

## 阶段判据

### G0：进入模型筛选前

- 已有至少 3 个不同项目的可执行案例；先验收 3 例再扩充。
- 目标故障可复现，fixed 版本可通过；失败签名与目标一致。
- 三组相同输入/工具权限；评测真值与求解器隔离。
- 模型入口、单任务预算、最长执行时间及运行记录经过验证。

未满足时处理环境和输入；此时训练或增加推理模块无从归因。

### G1：24 例开发筛选的继续信号

暂定满足任一信号即可扩大验证：

- 效果信号：P 相对 B1 净新增至少 2 个独立案例成功，并能从轨迹指出机制确实发挥了作用。
- 效率信号：总 Token 至少降低 20%，观察到的总成功数不低于 B1，且没有增加超时。

同时检查 B0：若 B1/P 均明显不如 B0，选择 B0 作为比赛基线，不因为做了新模块就强行保留。

这是筛选规则，不是显著性或非劣性证明。24 例看不到收益时，允许一次由具体失败原因支持的修改；再次无信号则暂停该增强，将剩余精力用于数据适配和验证可靠性。

### G2：独立确认和冻结

在查看确认集前锁定主要路线：

- 效果路线的目标：相对冻结最强基线提升至少 5 个百分点，并在独立案例的成对置信区间中支持正收益。
- 效率路线的目标：总 Token 至少减少 20%；独立测试通过率差异的置信区间下界高于预设 -2 个百分点的非劣界；同时报告实际费用和墙钟时间。

这些是建议目标。若组委会成本权重低或允许质量损失不同，应在确认前修改并记录。小样本区间不支持结论时，不用点估计宣称非劣性。

两个路线不能在同一测试集上反复挑选。若开发筛选后改换路线，使用新的确认数据。多方法/多阈值比较需要考虑多重比较，最终只冻结一个可部署配置。

## 如何衡量“诊断检查”本身

采纳率、拒绝率、未知率；有证据来源的诊断比例；探针实际得到有效观察的比例；机械事实检查失败率；新增成功与新增损害；检查的增量费用和时间。

不要把“引用了日志”当成“根因解释正确”，也不要用 LLM 自评分替代补丁验证。对诊断支持/矛盾样本做小批量人工审查，必要时双人复核争议。若探针会改变并发时序，或原故障不再复现，将其记为无效/受干扰观察，不据此否定根因。

回退必须真实运行：拒绝诊断后创建不含该诊断的新修复上下文，恢复原始代码状态，在剩余预算内继续。不能用另一条满预算基线的结果填进回退分支。

## 样本量与统计风险

预算工具给出的粗略样本量使用独立成对二元结果的正态近似：

    n ≈ (z(0.975) + z(0.8))² × (q - δ²) / δ²

δ 为预期绝对提升，q 为成对结果不一致概率。公式只用于规划量级，不代替精确功效分析；它忽略项目聚类、多次重复、阈值选择和多重比较，实际需求可能更大。

例如 q=0.20 时，希望检测 5 个百分点和 10 个百分点提升需要的独立样本量级差异很大。q 必须由开发数据估计，不能为了降低预算任意填写。因此 24 例筛选、60 例确认和正式论文实验承担不同任务。
