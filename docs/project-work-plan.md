职责：维护阶段顺序、依赖和验收门槛。实际进度只在 [STATUS](STATUS.md) 维护；算法与接口分别见 [设计草案](development/system-design-draft.md) 和 [模块规格](design-contracts.md)，指标以 [评测口径](preparation/metrics-and-gates.md) 为准。

## 目标和当前推进方式

目标产品是完成日志分析、根因行定位、补丁生成、实际运行验证和反馈自修复的 HarmonyOS 故障修复 Agent。用户提供任务、模型与检查配置，取得定位依据、候选补丁、检查及失败报告。正式截止为 2026-10-31；按用户安排，内部完成目标为 2026-10-24，包含真实测试结果、可复现作品和提交材料。用户并非全天开发，实测前只保留两个有限软件包，不按连续满日工时估算。候选模型为 deepseek-flash，账户、推理模式和 API 预算尚未确定；未获得执行条件前只做设计、实现和受管合成验收。

实测前的软件准备只围绕以下两项有限目标，不扩写通用 harness 或再开启高级演进。现有 CLI 不追加新功能，方法机制不以新增字段或来源核验代替业务验收。

| 目标 | 范围与完成门槛 |
|---|---|
| 软件包 A：核心上下文与业务输出 | 在已有存储/关系/发送边界实现阶段与业务义务驱动的决策工作集：替换平铺面板、完整原字段可回组、建议不授予权限，必要状态保留、相关证据优先、重复历史移出；保护初始/诊断后的跨文件探索和换根因后的最近真实失败，不新增数据库/框架/摘要服务。冻结候选可按行回读，文本替换复用 SDK 且失败不污染草稿。修正最终根因输出完整性及所选/备选区分，中间未知仍允许；覆盖阶段/草稿/未知、内容丢失、探索、长历史、反例、候选版本、同预算及完整工具组的局部反例，并验实际 SDK/wire 与恢复 |
| 软件包 B：产品与整链验收 | 已写 CLI 受管安装、help/version、参数/侧录、停止/恢复及实际 SDK/模拟传输整链；验预算内实际发送、原历史不变和完成恢复零新增调用。两个代表案例准备有限接口输入、独立预期、错误修复拒绝反例及观察接收端；真实候选/设备适配和完整业务检查在 P2 接纳，手工观察不算通过。选定提供方协议先做 fixture 接纳。锁与环境身份由安装同步，盘点不完整时停止，不重构平台 |

软件包 A 的审阅和测试设计不依赖云端模型或设备，可在安装阻塞时先推进；完整工程、oracle 或执行条件缺失不能按日历算完成。资源盘点不完整时停止受管安装和验收，不通过忽略目录或另起无保护入口完成；实际盘点与验收结果见 STATUS。此节点是可审查、可接真实输入的软件与准备材料，不保证修复效果。上下文增量只修改已有领域选择逻辑；上述目标不要求恢复跨任务晋升/研究成本/采值的延期实现。

请求/检查通道继续保持既有验收：复用 Deep Agents SDK、请求账本、候选和 Windows Job；云端配置、有限请求/响应、usage、失败与恢复，以及完整工程/候选/固定检查的执行边界不降低。analysis_source_v1 不能充作完整可构建工程。正常、格式错误、发送未知不盲重试、进程停止、预算、版本错配和恢复使用 Mock 与短时程序验证；凭据不得导出，真实开关关闭时明确拒绝。软件包 B 补选定提供方的显式模式参数、多轮工具及 reasoning_content 回传、合法空字段/中断终态、上下文策略兼容和恢复 fixture。DeepSeek 思考模式先保留完整历史并在上限停止，有限历史发送视图先在显式非思考模式验收；比赛最终模式由小额协议核验及开发结果决定，不默认放弃模型推理能力。fixture 兼容不等于真实服务已通过，协议细节归属设计与契约。

正式资源继续使用 resources/skills 的四类通用过程，原生 SDK Skill 管道与固定竞赛配置不另起实现。软件包验收目标是修复义务、条件化经验、有限工作集和失败反馈在同一循环贯通；模型推断不硬认证业务。整链验收读日志→定位/义务→编辑/候选→检查→反馈修订或诚实终止→报告/恢复，保存全部尝试与未知成本；核对实际请求中的决策布局、完整 Skill/经验正文、原失败版本及候选回读，不能只验盘上对象。演示与云端准备模板的选择分支一致；模板的显式模式须先接纳实际提供方，最终比赛模式由实测筛选。未执行真实应用检查时 application_verification=not_run、accepted=false；提交材料不能由合成通过填出应用成绩。

软件交付节点与实际应用验收、正式提交、论文扩展分别完成。自动 Skill 提炼/晋升、完整跨版本消费闭包、全生命周期 ResearchProfile 和自动运行采值冻结，不再继续补全为竞赛版前置；相关旧失败、来源与权限约束保留，后续若恢复扩展须按原标准继续验收。竞赛路径仍落实任务内预算，未知结果与停止/清理保护保留。SDK 隐式压缩/卸载继续关闭，可选主机压缩不继续横向扩展。实际完成及下一批只记 STATUS，不新增另一套进度台账。

软件包之后，实际云端兼容性、原故障复现、业务/回归、方法效果和真实成本仍须实测。计划在下表接入窗口取得模型及本机条件；未就绪时不能推定实验解锁。时间压缩时优先减少评测组合和已接纳案例扩展，不新增底座或用合成结果替代真实证据。

### 紧张时间下的停止扩展规则

只接一个模型提供方，用户候选 deepseek-flash 的实际模式/预算须在发送前确定；本机工具链先一例可用，再扩覆盖。缺预算不启动无界调用，预算不足时减少成对案例或组合并披露样本限制。若模型或设备迟于接入窗口到位，继续准备软件与判据，但不能保证内部日之前产生真实应用结果。长上下文机制若没有足够长的真实轨迹检验，其合成可靠性与真实收益分开报告；无收益或损害时选用已验基础策略，不为论文包装强行默认启用。

模板 README.md、technical-design.md、test-report.md 仅在最后的正式材料阶段填写。skill/ 的模板入口与 resources/skills 唯一正文对应，不在两个目录维护不同版本；私有源码/原始会话与可公开材料分别核准，不把未脱敏 delivery.zip 直接作为公开附件。

各阶段是工程条件，不要求每一步重新向用户申请确认。软件审阅与验收围绕两批 P0/P1 的门槛；下一阶段接纳 P2 执行条件，再开展 P3/P4，不把高级科研扩展放到真实接入之前。P1 通过不代表 P2/P3 的实际应用修复或 P5 正式提交已完成，模型和应用实验仍按当前用户安排暂缓。

新增通用工程须指出阻断的业务节点与最小验收，先查 SDK/SQLite/现成工具/追踪适配能否复用。原生 stream/callback 或可选 tracing 不要求新增服务部署；本机 owner/Job/预算/未知恢复不为降低工作量而绕过。当前不把框架迁移、全依赖闭包重构、MCP 化或追踪平台部署列入上述目标。

规模容量与任务耗时分别验收。两批复用 W07 已有材料/投影及静态 Skill 管道，按选定竞赛配置验完整路径；超限时减少重复核验，保留原字节、版本、链接、变化拒绝和历史恢复，不扩大默认截止时间或正式比较预算掩盖失败。代表规模的实际耗时必须注明计时范围，部分 I/O 或合成压力不证明全部 data_B 工程可运行。高级版本激活的读取容量失败只影响该扩展，不能被标为完成，也不阻塞未启用该扩展的竞赛路径。

## 本机真真实验的进入顺序

1. **只读盘点，不安装**：记录本机 CPU、内存、可用磁盘与可能的 GPU/显存，已装的 HarmonyOS SDK/Node/Java/hdc/构建工具、设备或模拟器及连接状态；核对两个代表案例的完整工程、构建脚本和场景入口。现有 `configs/local-runtime.json` 的轻量限额未验 SDK/模拟器校准，不直接放宽或启动重任务。
2. **先验收本机应用执行通道**：为项目专属 SDK/缓存及工作副本确定可归属路径和空间上限，新增受管构建、安装、目标回放、行为/回归任务与 Stop/清理核验；原版要在同一环境触发指定故障，正常行为有独立 oracle。设备占用、未结作业和资源超限不得被记作补丁错误。
3. **再接云端基础模型并打通 B0**：核对私仓代码/日志是否允许发往所选 API 及必要的脱敏边界，确定提供方、模型 ID、单任务调用/Token/时间与费用预算；本机 Agent 的每次请求验账本登记，先小规模验证工具调用、格式错误、usage、恢复和密钥边界，再在已接纳案例上运行具备反馈修订能力的基础 Agent。模型可用不代表应用验证已通过。
4. **最后做可比较的评测**：冻结开发/确认划分、共同验收协议、模型/工具/预算及运行配置。首轮只比较 B0/P，再按预算和信号决定 B1 与必要消融；规模与比较因素唯一维护在 [评测口径](preparation/metrics-and-gates.md)。设备任务串行并记录环境漂移、运行版本和全部失败/超时，汇总定位、功能、回归、首次通过和成本。论文主张只取有独立确认与消融支撑的增量。

既有请求/检查通道和竞赛闭环使用 Mock 与短时程序进行软件验收，实际完成范围见 STATUS。面向 HarmonyOS 工具链/设备的容量盘点、SDK/设备可用性、实际云端模型与数据调用边界未得到核定，W08 不因此自动解锁。真实端点配置或本机执行器代码存在不等于已允许真实实验。

### 每个工作包的接手步骤

1. 读 DEVELOPMENT、STATUS 和当前包对应的设计/规格段，确认 Git 修改归属。STATUS 给出的下一包决定当前范围；不要从头重写原型或重新选框架。
2. 在包内先完成一个最小正常路径，再加表中必须的失败路径。函数/私有类命名可自行选择；外部记录和状态语义服从契约。需要加文件时同步目录说明，避免无实现的占位层。
3. W01/W02 使用上述独立 PowerShell 自检；W03 后全部安装、pytest/Ruff/Pyright 和 Agent 运行都经 local.ps1 受管入口。目标 Run -Task test -TestPath tests/test_*.py 只接受现存仓库测试路径；实现时明确参数，不拼接任意 shell 字符串。
4. 新包通过本包必要测试及受影响旧测试，运行文档检查、审阅 diff 后提交。STATUS 记录包 ID、命令、结果、未决项和下一包；session 只记本批实际事实，不新建 handoff-final 等文件。
5. 若包尚未完成，交接要列准确的失败用例、触发命令和最小剩余改动。接口冲突、资源限制失效、数据/验收歧义不能靠扩大权限、放宽上限或修改测试绕过。

### 换模型后的执行约定

后续可交给 Luna 或其他模型完成有明确边界的工作包；计划不假设特定模型一定正确。一般实现细节由执行者处理；Job 资源/清理边界、候选原子性、计费完整性和效果结论以测试及证据为门槛，遇到未覆盖的设计冲突先具体报告，不跨多包自行改架构。审核只在出现实质风险或失败时升级，不要求每个小步骤向用户确认。

可直接使用的交接提示：

> 按 AGENTS.md、DEVELOPMENT.md、docs/STATUS.md 接手，从 STATUS 指定的下一工作包开始。工作包的依赖、修改范围和验收见 docs/project-work-plan.md。本批完成该包并提交，保留用户修改；资源数值来自 configs/local-runtime.json。禁止把未实现接口当成可运行命令，禁止放宽资源限制掩盖失败。按当前安排只做设计和合成软件自检，不启动模型或应用实验。结束时更新 STATUS 的实测证据和下一包；未完成就写明具体失败，不假报完成。

## 后续试验范围与调整规则

P2 先验收两个代表应用候选，再按预算和可用工具链扩类型。P4 的首轮规模、组别和扩展停止条件唯一维护在评测口径文档；不把数据盘点中的代表类型当作已接纳清单，也不默认开启完整消融矩阵。

输入不足、来源不明或环境不可运行的案例，在结果产生前登记处理规则。按应用/模板谱系划分开发与确认数据；重复日志、相似变体和重复运行不得增加独立样本数。后续规模依据可用独立案例与开发效果重新确定，不能沿用已归档的公开基准默认预算。

增强无收益时优先保留更稳的基础闭环。时间不足时先缩减新增机制和组合，保住输入适配、真实业务验证、自动终止及交付能力；交付目标和条件风险按上方排期执行，不将日期目标记为完成事实。确认集运行前锁定主要指标、比较配置与停止规则。
