## 目标和当前推进方式

目标产品是普通 Windows x64 本机可运行的源码/日志修复 Agent：配置云端模型后完成分析、根因行定位与补丁生成；接纳宿主验证器后实际执行原版和候选的相关源码、回放故障输入、检查行为并反馈修订。完整 HarmonyOS 工程、平台 SDK、签名、真机和模拟器不作为默认前置，application 全应用执行保留为可选扩展。正式截止为 2026-10-31；按用户安排，内部完成目标为 2026-10-24，优先完成可独立运行的系统、真实模型/宿主范围的测试结果和可复现作品；正式提交文档、精简session及提交版Git在测试完成并收到用户具体要求后整理。用户并非全天开发，不按连续满日工时估算。

用户于 2026-10-17 确认已在 configs/model.local.json 填好 Key，并授权有限总预算内开展真实 DeepSeek 测试。当前配置为 deepseek-flash、thinking enabled；以此进行小额兼容性接纳，不擅自关闭思考模式。批次总金额、保留额、保守费率及未知成本停止条件唯一维护在 [评测口径](preparation/metrics-and-gates.md#本次真实测试的总费用边界)，configs/evaluation.local.json 保存不含 Key 的私有执行清单。当前推进顺序为明确实际实现和数据形态、完成可独立使用的单例CLI与产物/费用展示、由用户执行小规模及剩余案例测试、复核汇总真实结果。正式提交模板、精简session和提交版Git待用户另给要求后进行；不在测试前重写提交材料。首例及扩展运行的实际结果仅见STATUS，021不再被指定为必须先完成的前置。预算约束优先于扩大样本和论文组合；不安装新依赖或平台 SDK，不运行完整 application 实验。

实测前的软件准备只围绕以下两项有限目标，不扩写通用 harness 或再开启高级演进。CLI 默认 analysis 无需执行配置，宿主检查用 --validation，完整应用扩展用 --application，二者互斥；只补直接阻断轻量交付的入口和检查。方法机制不以新增字段或来源核验代替业务验收。

| 目标 | 范围与完成门槛 |

| 软件包 B：轻量产品与整链验收 | Windows 完整项目一次安装、help/version、私有模型配置、analysis 默认入口与 --validation 宿主检查配置；生产运行不依赖 PowerShell/Codex，保留 Job、归属、预算和清理。通信继续复用官方 SDK，凭据不进入任务与证据，不扩建供应商框架。宿主 source 模式复用既有执行器，冻结相关源码、运行器、独立判据与语义范围，覆盖原版复现、候选回放、正常/边界与回归检查；平台 mock 明示，禁止用重写算法代替候选源码。analysis、synthetic、source_execution、application 的报告/退出码/恢复语义分别验收；旧配置/证据含义不变。验预算内发送、失败修订、原历史不变及完成恢复零新增调用；env/all 仍用退出后的独立解释器清理。代表案例宿主可运行性与真实提供方协议在 P2 接纳，不再等待 SDK/设备/签名 |

软件包 A 的审阅和测试设计不依赖云端模型或设备；软件包 B 在已有受管环境和短时程序上验边界，不据此宣称真实 `.ets` 或宿主验证器已接纳。缺独立判据或源码加载能力时仍允许 analysis，但不能给验证通过结论。资源盘点不完整时停止受管安装和验收，不绕过保护；实际结果见 STATUS。该节点交付可审查、可接真实输入的软件，不保证修复效果。上下文增量只修改已有领域选择逻辑，不恢复跨任务晋升/研究成本/采值扩展。

请求/检查通道继续复用 Deep Agents SDK、请求账本、候选和 Windows Job，云端请求、usage、失败/恢复及源码/检查绑定不降低。analysis_source_v1 可供分析和已接纳的局部源码回放，不冒充完整可构建应用。正常、格式错误、未知发送不盲重试、停止、预算、版本错配和恢复先用 Mock 与短时程序验证；凭据不得导出，运行仍须配置开关与批次预留共同放行。网络容错仍由 SDK 有限退避，只重试连接未建立的故障或明确 429；尝试数与逻辑调用分开，等待计入原请求/任务时限，旧缺 network profile 保持零重试。真实接入核显式模式、多轮工具及 reasoning_content、合法空字段/中断终态、usage、保存和恢复。当前 DeepSeek 思考模式要求保留并回传完整推理历史，不以裁剪必要历史实现省费；有限历史选择的效果不能由此模式的运行倒推。兼容性失败先修复并做合成检查，再核余量试跑，fixture 不代替真实服务。

正式资源统一使用根目录 skill/ 的标准 SKILL.md 与包内配套文件，原生 SDK Skill 管道不另起实现。整链验收读日志→定位/义务→编辑/候选→已配置检查→反馈修订或诚实终止→报告/恢复；核对实际请求、完整 Skill/经验、原失败和候选，不只验盘上对象。无执行配置可正常交出 analysis_completed/patch_proposed，但 accepted=false。报告 schema 4 的 source_verified/accepted=true 只表示宿主源码级协议通过，application_verification 仍为 not_run；application_verified 才是完整应用通过，旧 schema 1–3 不重解释。synthetic 仅为软件自检，不能填源码/应用成绩；官方最终评分是否接受某种宿主协议仍未知，材料必须披露验证范围。

软件交付、真实模型/宿主源码验收、正式提交与论文扩展分别完成。自动 Skill 提炼/晋升、完整跨版本消费闭包、全生命周期 ResearchProfile 和自动运行采值继续冻结，旧失败/来源/权限保留，恢复时按原标准另验。竞赛主线保留任务预算、未知不重发和停止/清理，SDK 隐式压缩/卸载仍关闭，不横向扩展主机压缩。实际完成与下一批只记 STATUS，不另建台账。

软件包之后，实际云端兼容性、原故障复现、业务/回归、方法效果和真实成本仍须逐项实测。模型测试授权已经取得，具体运行仍须通过只读预检、原版源码协议及累计预算门；执行证据只记 STATUS。时间压缩时优先减少评测组合和已接纳案例扩展，不新增底座或用合成结果替代真实证据。

### 紧张时间下的停止扩展规则

首轮真实验收只用已配置的 DeepSeek 提供方，不限制产品的同协议配置能力。同协议服务复用官方 SDK，不另写 HTTP 客户端；当前 thinking enabled 依提供方要求保留完整历史，不擅自更改用户模式。宿主验证按已接纳案例及真实覆盖缺口扩展，021不是必须先完成的前置；不为追求任意 `.ets` 自动执行而开发完整 ArkTS 编译器或平台模拟器。金额、Token、时间或已知性门阻断即停止付费，预算不足时减少成对案例或组合并披露样本限制。接入或语义问题先在本地修复，不连续付费重试，不等待设备。长上下文真实收益与合成可靠性分开，无收益或损害时选更稳策略，不为论文包装强行启用。

模板 README.md、technical-design.md、test-report.md 仅在最后的正式材料阶段填写。根目录 skill/ 是唯一标准 Skill 源库及提交入口，正文与 references/scripts/assets 随各包集中维护，不另保留生效的 JSON 定义；私有源码/原始会话与可公开材料分别核准，不把未脱敏 delivery.zip 直接作为公开附件。

各阶段是工程条件，不要求每步重新确认。软件审阅围绕 P0/P1，随后接纳 P2 的模型及宿主源码协议再开展 P3/P4，不把高级科研或可选平台扩展放在前面。用户的本次授权覆盖有限预算内的真实模型和数据测试；P1 通过、Key 已配置或只读查询成功均不代表 P2/P3 真实修复或 P5 正式提交完成，实际结论须逐例证据支持。

新增通用工程须指出阻断的业务节点与最小验收，先查 SDK/SQLite/现成工具/追踪适配能否复用。原生 stream/callback 或可选 tracing 不要求新增服务部署；本机 owner/Job/预算/未知恢复不为降低工作量而绕过。当前不把框架迁移、全依赖闭包重构、MCP 化或追踪平台部署列入上述目标。

规模容量与任务耗时分别验收。两批复用 W07 已有材料/投影及静态 Skill 管道，按选定竞赛配置验完整路径；超限时减少重复核验，保留原字节、版本、链接、变化拒绝和历史恢复，不扩大默认截止时间或正式比较预算掩盖失败。代表规模的实际耗时必须注明计时范围，部分 I/O 或合成压力不证明全部 data_B 工程可运行。高级版本激活的读取容量失败只影响该扩展，不能被标为完成，也不阻塞未启用该扩展的竞赛路径。

## 本机真实模型与宿主验证的进入顺序

1. **只读盘点及零推理预检，不安装**：核对 Windows x64、受管 Python、CPU/内存/磁盘和既有轻量运行时。受管 `Run -Task provider` 经官方 SDK 只查询模型列表/余额，并核对普通 Node 的类型剥离能力，不发送推理或修复请求。依授权开启 model 实验前后均保留资源限制，application/SDK 仍禁用；账户或运行时缺项先解决具体阻断，不放宽限额。
2. **接纳首例宿主源码验证**：先为 022 冻结相关源码映射、运行器、输入、独立预期及四项检查，再以相同规则接纳 021 等案例。build 表示局部语法/装载，target 执行故障输入，behavior/regression 检查正常与边界。原版和冻结候选都须实际执行对应源码；不得用 Python 重写算法、模型自建预期或旧日志重读自证。记录抽取/转译、mock、未覆盖平台语义与进程停止；不可等价部分保留未知，可继续提供未验证补丁。完整 application 的 SDK/签名/设备不在本次实验授权范围。
3. **小额接云端基础模型并打通首例**：只外发允许的源码/日志及必要上下文，不把构造答案、参考补丁、隐藏测试或私有模型配置放入求解输入。在已配置 DeepSeek 模式下，先确认私有批次清单、单任务调用/Token/时间和累计费用预留；有限调用验证工具续轮、reasoning_content、usage、保存、恢复和密钥边界，再在已接纳的 022 上运行具备反馈修订能力的 Agent。未知请求/费用默认阻断后续付费；用户显式接纳的冻结全额占用例外见评测口径，不能清除原未知或扩大总预算。缺陷先在本机修复。模型接入可用不代表源码或应用验证已通过。
4. **扩展覆盖，再做预算允许的比较**：接 021 和其余必要案例，冻结开发/确认划分、共同宿主协议、模型/工具/预算和运行配置。比较规模、B0/P 进入门及扩展条件唯一维护在 [评测口径](preparation/metrics-and-gates.md)。任务串行，保存运行时、源码/判据、mock、范围、全部失败/超时，分别汇总定位、源码级修复、局部功能/回归、首次通过和成本；未经 adapter 的 analysis 结果不能计源码成功。只有预算足够完整比较才启动额外组别，论文主张只取有独立确认与消融支撑的增量。

既有请求/检查通道和竞赛闭环先用 Mock 与短时程序验软件，真实执行证据只见 STATUS。用户 2026-10-17 的授权解除本次模型/数据测试禁令，不等于代表 `.ets` 协议已接纳、全量可回放或硬件实验获准；每例仍须通过 W08 对应层级的源码、判据与资源/预算门。

### 每个工作包的接手步骤

1. 读 DEVELOPMENT、STATUS 和当前包对应的设计/规格段，确认 Git 修改归属。STATUS 给出的下一包决定当前范围；不要从头重写原型或重新选框架。
2. 在包内先完成一个最小正常路径，再加表中必须的失败路径。函数/私有类命名可自行选择；外部记录和状态语义服从契约。需要加文件时同步目录说明，避免无实现的占位层。
3. W01/W02 的 PowerShell 自检仅保留历史兼容；生产安装、pytest/Ruff/Pyright/docs 和 competition 使用 Python 原生受管入口，历史研究/聚合/Export 可用原 local.ps1。Run -Task test -TestPath tests/test_*.py 只接受现存仓库测试路径，不拼接任意 shell 字符串，也不绕过资源限制。
4. 新包通过本包必要测试及受影响旧测试，运行文档检查、审阅 diff 后提交。STATUS 记录包 ID、命令、结果、未决项和下一包；session 只记本批实际事实，不新建 handoff-final 等文件。
5. 若包尚未完成，交接要列准确的失败用例、触发命令和最小剩余改动。接口冲突、资源限制失效、数据/验收歧义不能靠扩大权限、放宽上限或修改测试绕过。

### 换模型后的执行约定

后续可交给 Luna 或其他模型完成有明确边界的工作包；计划不假设特定模型一定正确。一般实现细节由执行者处理；Job 资源/清理边界、候选原子性、计费完整性和效果结论以测试及证据为门槛，遇到未覆盖的设计冲突先具体报告，不跨多包自行改架构。审核只在出现实质风险或失败时升级，不要求每个小步骤向用户确认。

可直接使用的交接提示：

> 按 AGENTS.md、DEVELOPMENT.md、docs/STATUS.md 接手，从 STATUS 指定的下一工作包开始。工作包的依赖、修改范围和验收见 docs/project-work-plan.md。本批完成该包并提交，保留用户修改；资源数值来自 configs/local-runtime.json。禁止把未实现接口当成可运行命令，禁止放宽资源限制掩盖失败。本次真实模型/源码测试须遵守评测口径的总金额、逐 run 预留和未知成本停止门，使用私有批次清单，不能单独新开运行重置预算；不运行完整 application 实验或安装平台 SDK。结束时更新 STATUS 的实际证据和下一包；未完成就写明具体失败，不假报完成。

## 后续试验范围与调整规则

P2 先接 022 的局部源码协议，首例通过即可开展其小额真实闭环，再逐例接纳 021 和必要覆盖；硬件相关语义无法覆盖不阻塞 analysis，但必须披露。P4 的首轮规模、组别和扩展停止条件唯一维护在评测口径，不把盘点中的代表类型当已接纳清单，也不默认开启完整消融矩阵。

输入不足、来源不明或环境不可运行的案例，在结果产生前登记处理规则。按应用/模板谱系划分开发与确认数据；重复日志、相似变体和重复运行不得增加独立样本数。后续规模依据可用独立案例与开发效果重新确定，不能沿用已归档的公开基准默认预算。

增强无收益时优先保留更稳的基础闭环。时间不足时先缩减新增机制和组合，保住输入适配、真实业务验证、自动终止及交付能力；交付目标和条件风险按上方排期执行，不将日期目标记为完成事实。确认集运行前锁定主要指标、比较配置与停止规则。
