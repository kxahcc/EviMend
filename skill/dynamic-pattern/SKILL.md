# 动态模式、输入语言与解析诊断

由输入动态构造的表达式或解析操作抛错、匹配异常或返回错误结果。需要先确定输入是字面文本、用户正则还是结构化格式，再调查构造、转义、flags、编码和状态。

适用线索：`dynamic_pattern`、`regex`、`parsing`、`literal`、`escaping`、`encoding`。

## 开始前要核对什么

### 1. input-language

已找到产品或调用方对输入语言的要求，能区分字面查询、允许用户编写的正则和结构化格式。

**未知时先查证：** UI、接口和下游结果定义是否允许正则语法？特殊字符应按原文本查找、作为语法解释，还是应明确提示无效输入？

### 2. construction-chain

已经核对原始输入到构造或解析点的完整变换，包括拼接、转义次数、flags、编码及表达式复用状态。

**未知时先查证：** 输入在哪一层变换？是否重复转义或遗漏转义？目标 API 支持哪些 flags 和语法，复用对象是否带有会影响后续匹配的状态？

### 3. results-and-invalid-input

正常结果集合、空输入、无效输入、错误反馈和资源过限的行为有可核对依据。

**未知时先查证：** 大小写、Unicode、匹配范围、捕获组和结果顺序怎样约定？空查询和无效模式应返回什么状态，允许的复杂输入怎样处理？

## 诊断、修复与验证过程

### 1. 追踪输入与语义

过程标识：`trace-input-and-semantics`。

从失败构造或解析点读取调用方、输入来源、每层变换和结果消费者。把原始文本、最终模式或解析值及对应 flags 分开记录。查清产品输入语言，语法错误本身不能决定应转义还是保留正则能力。

- **需求明确要求字面文本查找：** 比较符合大小写、Unicode 和匹配范围要求的字面匹配与一次正确转义，不把用户文本直接当模式。
- **需求明确允许用户正则：** 保留合法语法和 flags，定位拼接问题或无效输入，并查明错误反馈契约。
- **操作消费结构化格式或特定编码：** 核对格式边界、解码和对应解析接口，不能通过正则转义或删字符替代格式修复。
- **输入语言仍未知：** 查 UI、调用方或可信需求，记录字面与正则两种修法的不同结果，不默认选择一种。

### 2. 核对构造和复用状态

过程标识：`check-construction-and-state`。

核对构造点所用语法、拼接边界、转义层数和 flags，检查错误发生在构造还是执行阶段。复用带状态的表达式时调查状态如何更新及其业务含义。结构化解析另查原始编码、完整输入和格式约定；保留解析失败，不以部分解析值充当完整结果。

- **字面文本被误当语法或转义次数错误：** 在语义明确的边界修正匹配或转义，核对特殊字符仍按原文本处理。
- **合法模式因拼接、flags 或复用状态产生错误：** 修复对应构造或状态管理，保留合法模式能力；只有独立重复匹配的要求成立时才重置状态。
- **用户模式或结构化输入确实无效：** 按已有契约返回明确无效状态或错误反馈，不偷偷改输入或统一返回全部、空结果。
- **目标语法、编码或状态行为尚不确定：** 查询匹配的平台接口或取得主机批准的有限观察，保留未知，避免依赖其他运行时的表现。

### 3. 保持结果契约地修复

过程标识：`repair-with-result-contract`。

形成保持输入语言和结果契约的候选。字面搜索可采用相符的字面 API 或正确转义；用户正则须保留合法复杂模式并明确无效模式反馈；结构化输入须恢复正确的编码和解析边界。若复杂输入造成资源风险，只能按已有或主机批准的有界处理与明确失败协议处理，不能静默截断后声称完整匹配。

- **候选同时恢复构造和结果语义：** 冻结补丁，列出普通、特殊、空、复杂及无效输入的预期结果后进入固定检查。
- **候选吞错、改变输入语言或返回任意结果集合：** 把语义变化作为反例，回到调用方要求并修订，不能只检查不再抛异常。
- **合法复杂输入仍可能超过资源界限：** 保留成本及能力未知，核对明确的限制与失败反馈；不得自行无限重试或提高执行预算。

### 4. 验证输入语言与结果

过程标识：`verify-input-language-and-results`。

按固定协议检查普通文本、特殊字符、空输入、合法复杂模式、明确无效模式和适用的 Unicode、编码或重复调用。核对实际结果集合、顺序、捕获内容及错误反馈，记录候选和执行版本。匹配成功或构造不抛错分别只说明对应检查完成。

- **已有检查确认正常、特殊和无效输入的预期行为：** 保存实际覆盖及成本，交共同接受门判断；局部或模拟检查不取得应用资格。
- **构造成功但结果集合、状态或错误反馈不符：** 保留失败反例并回查输入语言、flags、状态和消费规则后修订。
- **检查超时、未运行或结果未知：** 停止新增执行，报告已有补丁与未验证输入范围，不补造结果或宣称性能及修复收益。

## 必须保留的行为

- 保留产品明确支持的输入语言，包括字面字符和合法用户模式各自的含义。
- 保留大小写、Unicode、匹配范围、结果顺序、捕获内容及重复调用的约定。
- 保留空输入、无效语法、格式错误和资源不足各自明确的反馈，不把它们伪装成正常空结果。

## 用来否定错误修法的反例

- 统一转义所有输入使字面搜索不再报错，却破坏产品允许的用户正则语法。
- 只给表达式构造加 catch 后返回全部或空集合，异常消失但查询语义错误。
- 在两层都转义特殊字符，表达式合法却匹配不到原本要求的文本。
- 同一带状态的表达式在重复调用时返回不同集合，单次通过不能证明复用正确。
- 删除不认识的字符或静默截断输入能使解析成功，却改变合法数据或交出不完整结果。

## 退出与结果边界

- 输入语言或结果契约与前提矛盾时停止照搬当前修法，重新调查调用方与需求。
- 平台语法、编码、复用状态或错误反馈无法确认时保留未知，不仅按异常名称决定补丁。
- 主机未允许执行、资源超限或任务预算耗尽时停止，保留全部尝试和费用未知项。
- 按实际检查级别报告；没有独立业务和回归检查时不得把无异常、模拟通过或局部结果写成应用成功。
