## 目录结构

```
.
├── README.md                  ← 你正在看的这个文件（请修改上方队伍信息）
├── docs/
│   ├── technical-design.md    ← 技术设计文档（必填）
│   └── test-report.md         ← 测试报告（必填）
├── sessions/                  ← Session 对话记录（必填）
│   └── template-session.json  ← 示例：一次 AI 辅助开发的对话记录
├── src/                       ← 功能源代码（必填，包含脚本和工具）
├── skill/                     ← Skill 技能定义和脚本
├── tests/                     ← 测试代码 / 测试用例
└── resources/                 ← 资源文件（知识库、数据等）
```
可按需自由添加其他文档和文件。


## Session 记录说明

开发过程中每次使用 AI 工具（Claude、ChatGPT、Cursor 等）进行的对话，都需要记录到 `sessions/` 目录下（记录与功能开发密切相关的session）。

### 记录规则

- **每次独立开发对话**保存为一个 JSON 文件
- 文件命名建议：`YYYY-MM-DD-简短描述.json`
  - 例如：`2026-09-01-用户登录模块.json`
  - 例如：`2026-09-05-性能优化.json`
  - 例如：`2026-09-10-bug修复-内存泄漏.json`
- 参考 `sessions/template-session.json` 的格式填写
- 不需要逐字复制 AI 回复，**摘要记录关键内容即可**

## 提交规范

- **截止日期前**打 tag 标记最终版本：
  ```bash
  git tag -a final-v1.0 -m "最终提交"
  git push origin final-v1.0
  ```
- 未打 tag 的以 main 分支最新提交为准
- 建议日常提交保持小粒度，写清楚 commit message

## 提交材料评分标准

| 维度 | 分值 | 说明 |
|------|------|------|
| 功能完整性 | 40 | 核心功能是否完整实现、技术创新 |
| 技术设计 | 20 | 架构合理、设计文档清晰 |
| 代码质量 | 20 | 可读性、结构、注释、规范 |
| 测试覆盖 | 10 | 测试用例充分、测试报告详实 |
| 工程规范 | 10 | Git 提交规范、目录结构、文档完整 |

**总分: 100 分**
