# EviMend

状态：研究开发入口。最后维护：2026-10-26。

**围绕故障假设、代码证据与验证反馈，研究软件缺陷的定位、修复和迭代验证。**

EviMend 是一个以云端大模型为推理基础的修复 Agent。系统读取源码与故障材料，检索相关实现，提出根因解释和代码补丁；在任务配置了执行协议时，检查原版与候选，并根据失败反馈继续修订。运行过程保存补丁、检查结果、上下文记录和资源用量，支持恢复与结果审阅。

项目面向独立的软件修复任务，以及缺陷挖掘系统发现问题之后的局部修复阶段。研究重点是证据怎样影响下一步调查、上下文选择和修复方向，通用 Agent 循环与模型通信复用 Deep Agents、LangGraph 和官方模型 SDK。

## 当前可用能力

| 能力 | 实现方式 |
|---|---|
| 源码与日志分析 | 文件读取、分页检索、栈位置映射及带来源的诊断记录 |
| 补丁生成与修订 | 独立草稿、冻结候选、实际 diff、失败反馈和有界迭代 |
| 执行验证 | 接纳任务运行器，在原版和候选上执行指定故障、行为及回归检查 |
| 上下文与过程指导 | 假设、证据、修复义务和决策记录；可选工作上下文；标准 Skill 按需读取 |
| 操作与复现 | CLI、事件输出、停止/恢复、模型调用与缓存用量记录、结果导出 |

当前部署范围为 Windows x64，模型通过云端 API 接入。新的跨项目执行环境与研究机制按[研究计划](docs/project-work-plan.md)逐步接纳。具体实现、验证范围和下一步见[当前状态](docs/STATUS.md)。

## 开始使用

已有普通 Python 3.11+ 的 Windows x64 主机可从项目根创建隔离环境：

```text
setup.cmd
dfx.cmd --help
dfx.cmd --demo --name demo01
dfx.cmd report demo01
```

演示使用固定响应模型，不调用云端，也不是修复能力评测。`dfx` 是沿用的兼容命令名，Python 包仍为 `dfx_agent`；项目更名保留运行接口和历史产物格式。

真实任务先配置模型，再准备源码/日志快照与可选验证协议。完整参数、任务格式及结果说明见[使用说明](src/dfx_agent/README.md)。模型调用需要明确的实验范围与费用上限，配置文件存在不表示可以自动发起新的研究实验。
